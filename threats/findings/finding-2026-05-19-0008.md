# CVE-2026-45829 ChromaDB pre-authentication RCE via HuggingFace model trust-chain abuse — unpatched as of 1.5.8 — 73% of internet-accessible deployments affected per HiddenLayer

## Summary

SecurityWeek (Ionut Arghire) reports CVE-2026-45829, a pre-authentication remote code execution vulnerability in ChromaDB — an open-source vector database widely used in LLM RAG (retrieval-augmented generation) pipelines. HiddenLayer originating research finds the flaw affects all ChromaDB versions since 1.0.0 and remains unpatched as of 1.5.8 (current release at article time). Per HiddenLayer assessment, approximately 73% of internet-accessible ChromaDB deployments are affected. The exploitation mechanism is a trust-chain ordering bug: the server processes client-supplied HuggingFace model identifiers and loads them BEFORE running authentication checks, enabling an attacker to trigger code execution by sending a crafted collection-creation request. Impact includes full server-process control, API keys, environment variables, secrets, and all files accessible to the ChromaDB process. Independent researcher Azraelxuemo co-disclosed the same class in November 2025 (pre-dating HiddenLayer per SecurityWeek attribution). HiddenLayer's recommended remediation requires moving the authentication check before configuration loading and removing `kwargs` keys from requests; the flaw remains unpatched at article publication. SecurityWeek does NOT claim in-the-wild exploitation; framing is research disclosure with anticipated weaponization risk.

## Technical detail

**CVE:** CVE-2026-45829

**CVSS:** Not disclosed in SecurityWeek; HiddenLayer primary not retrieved.

**Affected versions:** All ChromaDB iterations since version 1.0.0. Unpatched as of ChromaDB 1.5.8 (current release at article time).

**Vulnerability class:** Pre-authentication remote code execution via trust-chain ordering bug.

**Mechanism (conceptual per HiddenLayer via SecurityWeek):** Server trusts client-supplied model identifiers without restriction and acts on that trust before authenticating the user. Attacker sends a collection-creation request pointing to a crafted HuggingFace model; the server executes the model load operation before running authentication checks.

**Impact:** Full server-process control + access to API keys + environment variables + secrets + all files accessible to the ChromaDB process.

**Internet-accessibility statistic (per HiddenLayer via SecurityWeek):** Approximately 73% of internet-accessible ChromaDB deployments are affected.

**Caveat (Archimedes-recorded structural caveat):** The 73% figure references INTERNET-ACCESSIBLE deployments. Intra-VPN ChromaDB instances behind enterprise VPN / zero-trust gateways are NOT in HiddenLayer's scan basis. A&D-prime internal RAG/LLM ChromaDB deployments are likely insulated from this pre-auth network-perimeter exploitation class, but exposure depends on the specific A&D-prime deployment pattern.

**Remediation (per HiddenLayer via SecurityWeek):**

- Move authentication check before configuration loading
- Remove `kwargs` keys from requests
- Flaw remains unpatched as of article publication

**Exploitation language:** SecurityWeek does NOT claim in-the-wild exploitation. Framing is research disclosure with anticipated weaponization risk.

**Sibling pattern-class (Archimedes-recorded, NOT source-attested):** AI/ML supply-chain trust-boundary issues including Ollama RCE, llama.cpp deserialization, PyTorch pickle deserialization family. ChromaDB CVE-2026-45829 is the latest in a recurring pattern.
