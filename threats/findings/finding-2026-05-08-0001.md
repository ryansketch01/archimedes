# Linux kernel "Dirty Frag" LPE zero-day — public PoC, no patch, all major enterprise distros affected

## Summary

Researcher Hyunwoo Kim (@v4bel) disclosed on 2026-05-07 a Linux kernel
local privilege escalation flaw named "Dirty Frag" living in the
algif_aead cryptographic algorithm interface. BleepingComputer and SANS
ISC independently reported the disclosure on 2026-05-08; both confirm a
public deterministic PoC is available, no CVE is assigned, no patch is
generally available, and mitigation requires disabling esp4/esp6/rxrpc
kernel modules — which breaks IPsec VPNs and AFS. All major enterprise
Linux distributions (Ubuntu, RHEL, CentOS Stream, AlmaLinux, openSUSE
Tumbleweed, Fedora) are affected by a code path approximately nine years
old. No in-the-wild exploitation is yet asserted by an A-grade source,
but the predecessor flaw Copy Fail (CVE-2026-31431) lives in the same
subsystem and is KEV-listed with confirmed active exploitation as of
2026-05-01.

## Technical detail

Dirty Frag is a chain of two kernel weaknesses in the algif_aead crypto
algorithm interface. The flaw targets the fragment field of a kernel
data structure (the source of the "Frag" name), distinguishing it from
the conceptually related Dirty Pipe (CVE-2022-0847) and from the
recently-disclosed Copy Fail (CVE-2026-31431) which lives in the same
broader subsystem and is KEV-listed with active exploitation since
2026-05-01 (per finding-2026-05-04-0002).

The exploit is deterministic (no race condition required) — removing one
of the most common practical barriers to weaponization. The vulnerable
code path has been present in mainline Linux for approximately nine
years, meaning all currently-supported enterprise Linux distributions
are affected.

Mitigation per the disclosure: disable the esp4, esp6, and rxrpc kernel
modules. This mitigation breaks IPsec VPNs and AFS file systems —
operationally costly for many enterprise environments, particularly any
A&D contractor running site-to-site IPsec tunnels into supplier networks
or research-shared filesystems.

NVD has not yet issued a CVE.
