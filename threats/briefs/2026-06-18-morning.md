# Morning Brief — 2026-06-18

**UPDATE: A ~74,000-firewall Fortinet credential dataset surfaced by Hudson Rock and Bob Diachenko is authentic per four independent IR vendors — and Fortinet denies it's a fresh compromise.** Microsoft MSTIC separately documents an `@mastra` npm supply-chain compromise that weaponized 140+ AI-agent-framework packages overnight 2026-06-17.

**Why it matters:** Two DIB-adjacent exposures landed this cycle. Any org that ran `npm install` against `@mastra` after 01:01 UTC 2026-06-17 is potentially compromised regardless of whether the package was imported. Any Fortinet VPN operator should treat its credential corpus as suspect — even if Fortinet's reshare-plus-bruteforce framing wins.

## 🚨 Active Threats

**[UPDATE] FortiBleed — dataset authenticity holds across four IR vendors; vendor denial creates conflict surface**

- What: Security Affairs becomes the sixth publisher to consolidate Hudson Rock's analysis of a credential dataset covering ~74,000 Fortinet firewall URLs across 21,632 domains in 194 countries (~half of all internet-facing Fortinet firewalls per Shodan). Kevin Beaumont independently verified — "the data is legit" — and noted exports include configuration data only visible from the device itself, distinct from the 2025 Belsen Group leak.
- Conflict surface: Fortinet denies a fresh compromise and characterizes the dataset as reshared prior leaks plus present-day brute-force activity (vendor framing over the quote ceiling; paraphrase only). Substrate is resolution-pending; the vendor's first-party-equivalent device telemetry is weighted alongside the four external IR vendors, not discounted by publisher count.
- Named victims: Hudson Rock's domain extraction places Siemens (German industrial conglomerate; defense business is a minority segment), Foxconn, Samsung, Lenovo, Oracle, and Chevron in the dataset. Hudson Rock **alleges** full compromise of at least four orgs including a Turkish NATO defense contractor with **alleged** classified-defense-document theft — single-IR-vendor allegation pathway.
- Contrary evidence: Zero U.S. A&D primes (Lockheed, Northrop, Raytheon, Boeing, L3Harris, GD) named despite the dataset covering half of internet-facing Fortinet firewalls.
- Attribution: "Russian-speaking multi-operator threat group" per Diachenko — Hard Rule 2 verbatim. **No cross-walk to APT28, Sandworm, Gamaredon, Forest Blizzard, or FIN6.**
- Action: Fortinet VPN operators should treat the credential corpus as suspect regardless of framing, audit for credential-stuffing patterns, and rotate VPN credentials.
- Source: [Security Affairs](https://securityaffairs.com/) + [Ars Technica](https://arstechnica.com/) + [The Register](https://www.theregister.com/) + [BleepingComputer](https://www.bleepingcomputer.com/) · Digraph: B2 · WEP: dataset authenticity **likely**; named-corporate-victim **likely**; Turkish NATO contractor **possibly**; classified-document exfiltration **possibly**; vendor-denial resolution **roughly even chance**
- Related: [finding-2026-06-17-0002](../findings/finding-2026-06-17-0002-socradar-fortibleed-30000-compromised-fortinet-firewalls-credential-stuffing-defense-industry-vpn-endpoint-single-weak-indicator.md) · 🔗 **Update on:** 2026-06-17 morning + afternoon briefs.

**Microsoft MSTIC documents `@mastra` npm supply-chain compromise — 140+ packages poisoned overnight**

- What: MSTIC primary research (23:43 EDT 2026-06-17) documents an `ehindero` npm maintainer-account takeover that pushed an `easy-day-js` typosquat of `dayjs` (57M+ weekly downloads) into 140+ packages across the `@mastra` AI-agent-orchestration scope. Weaponized v1.11.22 published 01:01 UTC 2026-06-17.
- Payload: A 4,572-byte obfuscated `setup.cjs` postinstall dropper fetches a ~41 KB second-stage implant. Cross-platform persistence using the misspelled artifact `protocal.cjs` (Windows registry Run keys, macOS LaunchAgent, Linux systemd user units). Windows variant performs reflective .NET assembly injection. Cryptocurrency harvesting against 166 browser-extension IDs.
- Exposure scope: Any workstation or CI/CD pipeline that ran `npm install` against `@mastra` after 01:01 UTC 2026-06-17 is potentially exposed **regardless of whether the package was imported** — postinstall fires at install time.
- Attribution: "Organized threat actor activity" per MSTIC — verbatim. **No cross-walk to TeamPCP, Shai-Hulud, Lazarus, or any DPRK npm cluster.**
- Action: DIB orgs with `@mastra` in a Node.js / TypeScript pipeline: rotate build-environment tokens; hunt `protocal.cjs`, DNS to `tutamail.com`, traffic to `23.254.164.0/24`. Frank's Node.js/npm CI-CD pipeline status is not operator-confirmed.
- Source: [Microsoft MSTIC](https://www.microsoft.com/en-us/security/blog/2026/06/17/postinstall-payload-inside-mastra-npm-supply-chain-compromise/) · Digraph: A2 · WEP: campaign identity **likely** (single-A-IR-vendor); CI/CD exposure surface **very likely**
