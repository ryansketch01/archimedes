# SecurityWeek + Cyera: Ollama CVE-2026-7482 "Bleeding Llama" — heap OOB read in GGUF loader, ~300K exposed instances, patched in 0.17.1

## Summary

SecurityWeek (2026-05-05 08:39 EDT) reports research from Cyera disclosing CVE-2026-7482 in Ollama, a heap out-of-bounds read in the GGUF model loader that an unauthenticated remote attacker can trigger via a malicious GGUF file with a declared tensor offset or size that exceeds the file length. Cyera's exploitation chain abuses Ollama's built-in model-push feature to exfiltrate the resulting buffer — including stolen heap content (prompts, environment variables, API keys, recent user interactions, code under analysis, PII / PHI sitting in process memory) — to an attacker-controlled server. CVSS 9.3 per SecurityWeek; patched in Ollama 0.17.1; no public PoC reported; no in-the-wild exploitation reported. Cyera attributes ~300,000 internet-reachable Ollama instances to Ollama's default-bind-all-interfaces, no-authentication-by-default posture. The source is single-effective (SecurityWeek relays Cyera) — single-source veto caps WEP at "likely." This is a precautionary patch posture, not an active-exploitation event; FLASH does not trigger.

## Technical detail

- **CVE:** CVE-2026-7482 (per SecurityWeek; NVD record not yet independently confirmed in our pipeline).
- **Researcher name for the vuln:** "Bleeding Llama" (per Cyera).
- **Class:** heap out-of-bounds read in C/C++ file-format loader.
- **Affected component:** Ollama GGUF model loader.
- **Exploit prerequisites (per Cyera):**
  - Network reachability to Ollama port (default 11434).
  - No authentication required (Ollama default).
  - No prior compromise required.
- **Exploit primitive:** three unauthenticated API calls plus a malicious GGUF file in which the declared tensor offset or size exceeds the file length. Loader reads beyond the file buffer, returning adjacent heap memory.
- **Exfiltration primitive (per Cyera, single 15-word quote):** "The attacker then leverages Ollama's built-in model push feature to exfiltrate the resulting file."
- **Information disclosed via heap content:** prompts and message contents, environment variables (commonly API keys, tokens, secrets injected at process start), recent user interactions, code under analysis, PII / PHI sitting in process memory.
- **CVSS:** 9.3 Critical (per SecurityWeek; original Cyera scoring not separately verified at grading time).
- **Status:** patched in Ollama 0.17.1. No public PoC reported. No in-the-wild exploitation reported.
- **Internet exposure:** ~300,000 Ollama instances reachable from the internet per Cyera (methodology not independently verified at grading time).
- **Mitigations recommended (per Cyera):** patch to 0.17.1; restrict network access (bind to localhost; firewall the listener); deploy an authentication proxy in front; segment away from sensitive service tiers.

## A&D relevance

**No defense or aerospace targeting is mentioned — this is a vulnerability disclosure, not a campaign.**

**Plausible A&D exposure pattern:**

- DoD AI initiatives and prime R&D programs increasingly use self-hosted LLM inference. Ollama is one of the more popular open-source runtimes for that pattern.
- Heap content includes "environment variables (API keys, tokens, secrets)" — at a prime, those plausibly include cloud credentials, internal service tokens, and prompts containing project-coded names. A single unauthenticated pull against an exposed Ollama listener is therefore high-value if a prime has stood one up without controls.
- The relevant misconfiguration class is "default bind to all interfaces, no authentication." Hunt scope: any Ollama listener (default 11434) on RFC-1918 internal interfaces or — worse — externally reachable, across an enterprise estate.

**Calibration discipline:** no observed exploitation. Frame as a precautionary patch on a 14-day rolling window, not as an active-exploitation event. **FLASH triggers do NOT fire** — no exploitation, no actor, no A&D-direct campaign per FLASH-POLICY.md.
