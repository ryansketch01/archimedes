# Morning Brief — 2026-05-08

**[Ivanti EPMM CVE-2026-6973](../vulnerabilities/_index.yaml) is KEV-listed with a federal patch deadline 48 hours from now (2026-05-10), exploited in the wild against "a very limited number of customers" per Ivanti.** On-prem EPMM only — cloud variants unaffected.

**Why it matters:** Any DIB contractor still running on-prem MDM is in scope. The CVE is admin-auth-required, but Ivanti's January 2026 credential-rotation guidance is the load-bearing mitigation — non-rotators face a plausible chained path from prior unauth RCEs ([CVE-2026-1281](../vulnerabilities/_index.yaml) / [-1340](../vulnerabilities/_index.yaml)) into full MDM compromise. **Patch to 12.6.1.1 / 12.7.0.1 / 12.8.0.1 by Sunday.**

## Active Threats

**Ivanti EPMM CVE-2026-6973 — KEV deadline 2026-05-10, on-prem only.** Per [CISA KEV](https://www.cisa.gov/known-exploited-vulnerabilities-catalog), Ivanti PSIRT, and [NVD](https://nvd.nist.gov/vuln/detail/CVE-2026-6973): admin-authenticated RCE in on-prem EPMM, CVSS 7.2, patches shipped same-day with disclosure. Ivanti characterizes exploitation as "a very limited number of customers" (verbatim, 8 words). [SecurityWeek](https://www.securityweek.com/ivanti-patches-epmm-zero-day-exploited-in-targeted-attacks/) introduces an editorial chained-exploitation hypothesis — CVE-2026-6973 paired with January 2026 unauth RCEs CVE-2026-1281 / -1340 against customers who skipped credential rotation. [Shadowserver counted >850 exposed EPMM IPs pre-disclosure](https://www.securityweek.com/ivanti-patches-epmm-zero-day-exploited-in-targeted-attacks/) (508 Europe, 182 North America). Cloud variants (Neurons, EPM, Sentry) NOT affected. **No tracked-actor attribution** — SecurityWeek's "Chinese threat actors are often suspected in Ivanti zero-day attacks" is editorial pattern-of-history, not attribution to this CVE (Hard Rule 2). Procedural facts confirmed (A1); exploitation expansion if unpatched is **likely** (red-team-adjusted from very_likely on effective-single-source: Ivanti is the sole primary witness to exploitation; same-day KEV listing endorses rather than independently verifies). Bundle also patches four non-exploited CVEs ([CVE-2026-5786](../vulnerabilities/_index.yaml) / [-5787](../vulnerabilities/_index.yaml) / [-5788](../vulnerabilities/_index.yaml) / [-7821](../vulnerabilities/_index.yaml)). Digraph: A1 (procedural) / forward: likely · finding-2026-05-08-0002.

**Linux kernel "Dirty Frag" LPE — public PoC, no patch, all major distros.** Per [BleepingComputer](https://www.bleepingcomputer.com/news/security/new-linux-dirty-frag-zero-day-with-poc-exploit-gives-root-privileges/) and [SANS ISC](https://isc.sans.edu/diary/rss/32968): Hyunwoo Kim (@v4bel) disclosed a deterministic-no-race LPE in `algif_aead`; ~9-year-old code path; Ubuntu / RHEL / CentOS Stream / AlmaLinux / openSUSE Tumbleweed / Fedora all affected. Mitigation (disable esp4 / esp6 / rxrpc) breaks IPsec VPNs and AFS — operationally costly for site-to-site IPsec into supplier networks. No CVE assigned; no in-the-wild exploitation reported by any A-grade source as of compose. Same algif_aead subsystem family as [Copy Fail (CVE-2026-31431)](../vulnerabilities/_index.yaml), KEV-listed 2026-05-01 with confirmed active exploitation. **Likely** to follow Copy Fail's ~3-week disclosure-to-active-exploitation curve — caveat: this rests on a single-data-point base rate, and the assessment is medium-brittleness. **Tripwire 2026-05-22:** if no A-grade exploitation surfaces by then, this WEP drops to "roughly even chance." Digraph: B2 · WEP: likely · finding-2026-05-08-0001.
