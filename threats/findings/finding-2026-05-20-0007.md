## Technical detail (per Hard Rule 3 — TTP-class only; no PoC reproduction)

**Second-bypass mechanism class (per SW; no PoC reproduction):**

- SOCKS5 hostname null-byte injection
- Network-allowlist filter (e.g., a user policy allowing only `*.google.com`) sees the trailing `.google.com` in a crafted hostname and approves the connection
- OS truncates the hostname at the null byte during DNS resolution / connection
- Result: outbound connection dials the attacker-controlled host (the portion BEFORE the null byte) rather than the allowlist-approved host (the portion AFTER)
- Effect: bypass of the network-restriction sandbox component of Claude Code

**Researcher's exploitation chain framing (per SW):**

- "Comment and Control" — researcher-coined prompt-injection vector name (NOT an attributed campaign or actor)
- Chained with SOCKS5 null-byte bypass for outbound exfiltration
- Stated impact: "environment variables, credentials, tokens, and infrastructure data" exfiltrated from Claude Code execution context

**Patch timeline (per SW):**

- Vulnerability present in Claude Code: 2025-10-20 through 2026-03-31
- Fix committed: 2026-03-27
- Shipped in Claude Code 2.1.88: 2026-03-31
- Researcher reported to Anthropic: 2026-04-03 (POST-patch coordinated disclosure observed by researcher via independent commit / version diff)

**Vendor disposition (per SW researcher commentary):**

- No CVE assigned to second bypass
- Not mentioned in Claude Code 2.1.88 release notes
- Marked as duplicate by Anthropic via HackerOne
- No public acknowledgement

**First bypass (separate, has CVE):**

- CVE-2025-66479 — assigned to the 'sandbox-runtime' library
- Configuration-related, NOT the SOCKS5 mechanism
- Earlier coordinated disclosure timeline
