# CVE-2026-40361 Outlook Zero-Click UAF — Haifei Li / Expmon Discovery, Explicit BadWinmail Equivalence, PoC-Only / No ITW

## Summary

SecurityWeek's 2026-05-13 editorial extends Microsoft's May 2026 Patch
Tuesday CVE-2026-40361 disclosure with three new claim layers: discoverer
attribution to **Haifei Li**, developer of the Expmon zero-day detection
system; explicit historical equivalence to **CVE-2015-6172 (BadWinmail)**,
the 2015 Outlook preview-pane RCE that drew "enterprise killer" framing
at the time; and clarification that Haifei Li **developed only a PoC**
rather than a working exploit achieving code execution. The flaw is a
**zero-click use-after-free in a DLL shared by Microsoft Word and
Outlook**, exploitable via Outlook's email preview pane without any
user interaction. Microsoft patched it via the 137-vuln May 2026 Patch
Tuesday cohort and **states no in-the-wild exploitation observed** at
disclosure. The parent finding-2026-05-12-0003 covers CVE-2026-40361 as
a Word RCE pair partner; this finding adds the Outlook-zero-click
framing, the named-researcher attribution, and the BadWinmail historical
analogy that elevates the forward-looking weaponization-risk profile.

## Technical detail

### CVE-2026-40361 — Outlook Zero-Click UAF (BadWinmail-class)

- Product: Microsoft Outlook (all currently-supported channels);
  Microsoft Word (all currently-supported channels); Microsoft Office
  (shared DLL component)
- Class: Use-after-free memory corruption in a DLL shared between
  Word and Outlook
- Severity: Critical (per parent finding-0003 MSRC enumeration; CVSS
  score not exposed in SecurityWeek editorial — vuln-tracker NVD-lag
  backfill action; preview-pane zero-click UAF RCE class typically
  scores 8.1–9.0 v3.1)
- Attack vector: Network, email preview pane, zero-click — triggered
  when a victim reads or previews a malicious email in Outlook with
  no user interaction beyond receiving the message
- Authentication required: No
- User interaction: None (zero-click via preview-pane rendering)
- ITW exploitation: Not observed per Microsoft at disclosure
- PoC status: Haifei Li / Expmon disclosed a PoC only; **no working
  exploit achieving code execution** developed by the researcher (per
  SecurityWeek relay of Li's statement)
- Patch: Available at disclosure via Microsoft May 2026 Patch Tuesday
  (137-vuln cohort), 2026-05-12

### Historical equivalence — CVE-2015-6172 (BadWinmail)

SecurityWeek's editorial layer makes an **explicit equivalence claim**:
CVE-2026-40361's attack vector and potential impact mirror CVE-2015-6172
(BadWinmail), discovered by Haifei Li over a decade ago. BadWinmail
was an Outlook preview-pane RCE in shared TNEF parsing logic; it was
called an "enterprise killer" at the time because it enabled CEO/CFO
compromise via emailed exploit with no recipient interaction.

The attack-vector parallel is direct: preview-pane zero-click RCE in
a shared Office DLL, triggered by reading or previewing a message in
Outlook.

### Forward-looking weaponization-risk profile

Prior Outlook zero-click / preview-pane classes have been weaponized
by tracked nation-state actors within weeks of disclosure:

- **CVE-2015-6172 (BadWinmail, 2015)** — referenced by SecurityWeek
  today; "enterprise killer" framing
- **CVE-2017-11882 (EQNEDT32 equation editor)** — weaponized across
  multiple campaigns within months
- **CVE-2021-40444 (MSHTML)** — weaponized within weeks; multi-actor
  exploitation
- **CVE-2023-23397 (Outlook NTLM)** — weaponized by APT28 within ~2
  weeks of disclosure; widely deployed across European-government /
  military targeting (Ukraine, Romania, Poland)
- **CVE-2024-21413 (MonikerLink)** — Proofpoint published full
  weaponization chain within ~3 weeks of disclosure

The PoC-only status today means the immediate operational risk is
LOW for organizations that patch promptly via Patch Tuesday. The
forward-looking weaponization risk is HIGH if any tracked actor
develops a working exploit before the 137-vuln cohort patch
deployment completes across enterprise estates.
