# Tycoon2FA PhaaS kit rebuilt after law-enforcement disruption, pivots to OAuth device-code phishing against Microsoft 365

## Summary

BleepingComputer (Bill Toulas, 2026-05-17 10:43 EDT) relays eSentire vendor research that the Tycoon2FA phishing-as-a-service kit — disrupted by law enforcement action earlier in 2026 — has been rebuilt and now incorporates OAuth 2.0 device-code phishing against Microsoft 365 accounts. The mechanism abuses the device authorization grant flow (RFC 8628) to broker session-token capture from an attacker-controlled device, bypassing subsequent MFA. Lures route through legitimate Trustifi click-tracking URLs and a fake Microsoft CAPTCHA page that brokers OAuth device-code consent.

The mechanism class (device-code phishing) is independently well-established via MSTIC Storm-2372 (February 2025), Volexity Russian SVR 2025 reporting, and MITRE ATT&CK T1528 — making the mechanism layer A1 even though eSentire's specific Tycoon2FA-pivot claim is single-sourced through the BleepingComputer relay. ## Technical detail

**Mechanism (per BleepingComputer relay of eSentire):** OAuth 2.0 device authorization grant flow (RFC 8628) abused as follows:

1. Victim receives phishing email containing a legitimate Trustifi click-tracking URL (Trustifi is a legitimate email-security vendor; URL surface is being abused, this is NOT a Trustifi-side vulnerability).
2. Click-through redirects to a "fake Microsoft CAPTCHA page" (eSentire framing per BleepingComputer).
3. The fake-CAPTCHA page brokers an OAuth device-code consent request to an attacker-controlled device — i.e., the victim's browser is being used to authorize an attacker-side device-code grant.
4. Once the victim grants consent, the attacker-controlled device holds a session token bearing the victim's M365 entitlements.
5. Subsequent MFA challenges on the targeted account do NOT bind the attacker's session token — the device-code grant has already provisioned a valid token that does not re-trigger interactive auth flows.

**Mechanism corroboration (independent of eSentire/Tycoon2FA-specific claim):**
- RFC 8628 — IETF OAuth 2.0 Device Authorization Grant standard (foundational reference)
- MITRE ATT&CK T1528 — Steal Application Access Token (documented technique)
- MSTIC Storm-2372 — February 2025 primary research on a nation-state actor using the same device-code-phishing mechanism (different actor, same mechanism — corroborative on mechanism class only)
- Volexity Russian SVR campaign reporting — 2025 reporting on a separate actor using the same mechanism class

**Single-sourced claims (BleepingComputer/eSentire only):**
- Tycoon2FA-operator attribution of THIS specific campaign
- "37x year-over-year surge" in device-code phishing (methodology not retrievable from relay)
- Specific use of Trustifi click-tracking URLs as the lure-chain redirector

**Quoted detail (15-word limit per Hard Rule 6):** "Device code phishing has become highly popular among cybercriminals" (12 words; eSentire framing per BleepingComputer; single quote per source preserved).
