# NASA F´ (F Prime) flight software framework CVE-2026-41144 — FileUplink integer overflow chains to arbitrary file write and RCE on embedded targets; NVD 9.8 vs vendor 0.0 CVSS divergence (third such instance this week); patched v4.2

## Summary

NVD and NASA F´ (vendor-authority-on-own-product) jointly disclose CVE-2026-41144, an integer overflow in the F Prime flight software framework's FileUplink component that chains with absent path-traversal sanitization to produce arbitrary file write and remote code execution on embedded targets. NVD scores the bug 9.8 CRITICAL based on inherent network-exploitability and full-CIA impact; the NASA F´ vendor GHSA scores it 0.0 Low with all impacts "None" — a 9.8-point divergence reflecting different mental models (NVD scores code properties; vendor scores deployment posture on mission-specific embedded targets). Affected version v4.1.1; patched v4.2 (commit bb585fe35a728bb69c157c6689f3b7a9f8a4f546). Discovered by bitWarrior. No active exploitation reported. No KEV listing. No actor attribution. This is the third CNA-vendor-vs-NIST-uplift instance observed in 24 hours (alongside NVIDIA TRT-LLM in this morning's finding-0003 and ISC BIND 9 in this afternoon's finding-0011 — pattern matters for vuln-tracker triage).

### CVSS divergence analysis (Archimedes-side framing, A2)

NIST/NVD scored 9.8 CRITICAL based on network exploitability (AV:N) and full CIA impact (C:H / I:H / A:H). Vendor GHSA scored 0.0 Low with all impacts "None."

The most-likely explanation (operator-side interpretation, not vendor's): the vendor reasons that F´ Flight Software is deployed on isolated mission-specific embedded targets (spacecraft, CubeSats, rovers, planetary probes) — not on network-reachable internet hosts. The operational "network" is the ground-link command channel, which is authenticated and access-controlled at the mission-ops level. NVD's mental model scores the bug as a code property, not as a deployment posture.

The pattern matters because **defenders reading purely from NVD will treat this as 9.8 critical; teams reading the vendor advisory will see 0.0 Low and de-prioritize.** For spacecraft flight-software development teams running pre-launch test environments where network reachability IS present (developer workstations, ground-test simulation environments, integration labs), the NVD score is the more relevant reading. For flight hardware on-orbit, the vendor's 0.0 reflects practical exposure.
