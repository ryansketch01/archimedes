# F5 K000160932 Quarterly Advisory — CVE-2026-42945 "NGINX Rift" 18-Year-Old Pre-Auth RCE Class (50+ CVE Cohort)

## Summary

F5 published quarterly security advisory K000160932 on 2026-05-14 disclosing 50+ vulnerabilities across NGINX, NGINX Plus, BIG-IP, BIG-IQ, NGINX Ingress Controller, and App Protect WAF. The headline CVE is **CVE-2026-42945** ("NGINX Rift" per researcher depthfirst), a heap buffer overflow in NGINX's rewrite module with CVSS v4.0 base score 9.2. A single crafted HTTP request with unnamed PCRE captures plus a question mark replacement triggers the overflow without authentication — pre-auth RCE class when ASLR is disabled, denial-of-service via worker process crash when ASLR is enabled (standard hardened configuration).

F5 reports no in-the-wild exploitation observed at disclosure. Patches are available across all affected NGINX product lines (Plus R32 P6+ / R36 P4+, Open Source 1.30.1 / 1.31.0, Ingress Controller, App Protect WAF). The cohort additionally includes CVE-2026-41225 (iControl REST authenticated privesc, CVSS 8.6) and CVE-2026-41957 / 34176 / 39459 (BIG-IP authenticated-RCE family).

The "18-year dormancy" framing originates from The Hacker News + researcher depthfirst editorial commentary, not from F5's K000160932 advisory itself per available extraction. That framing is graded B3 in the layered digraph and should be presented as headline color rather than load-bearing claim. The load-bearing vendor-attested facts (CVE existence, CVSS, patches available, no active exploitation) are A1 vendor-primary.

A&D-prime relevance is structural / indirect: NGINX is the dominant web-tier / reverse-proxy / ingress-controller / load-balancer software across prime infrastructure (Boeing / Lockheed Martin / RTX / Northrop / General Dynamics / BAE / L3Harris / Leidos / SAIC / Thales / GE Aerospace / Safran / Honeywell Aerospace / Airbus typically run NGINX, NGINX Plus, BIG-IP with embedded NGINX, or NGINX-based Kubernetes ingress somewhere in the stack). No A&D-prime is named as a customer in K000160932; the indirect-deployment-exposure is the relevance vector.

## Technical detail

### Trigger pattern (per depthfirst via THN)

The vulnerability triggers "when the rewrite directive is followed by a rewrite, if, or set directive and an unnamed Perl-Compatible Regular Expression (PCRE) capture (for example, $1, $2) with a replacement string that includes a question mark." (15-word quote within Hard Rule 6 limit; paraphrased remainder.)

A single crafted HTTP request with URI data designed to trigger this pattern corrupts the heap. No authentication required, no prior access required, no existing session required.

### Severity caveat — ASLR dependency

Code execution is "possible" primarily on systems with Address Space Layout Randomization (ASLR) disabled. Standard hardened deployments with ASLR enabled (modern Linux distribution defaults) limit impact to denial-of-service via worker process crashes.

For A&D estate assessment, the ASLR configuration state is the determining factor:

- Modern Linux distribution defaults ship ASLR enabled — standard hardened web-tier deployments should be ASLR-on.
- Legacy deployments on older / less-curated infrastructure may have ASLR disabled — vendor appliances with embedded NGINX, BIG-IP-embedded NGINX, internally-administered Kubernetes ingress controllers, IoT/OT-adjacent NGINX-on-embedded-Linux platforms.
- F5 K000160932 likely includes specific configuration-state guidance; defer to vendor primary for authoritative posture recommendations.

### Patched versions

- NGINX Plus: R32 P6+, R36 P4+
- NGINX Open Source: 1.30.1, 1.31.0
- NGINX Ingress Controller: specific versions per F5 advisory
- NGINX App Protect WAF: specific versions per F5 advisory

### Pre-patch workaround

For organizations unable to patch immediately, replace unnamed PCRE captures with named captures in every affected rewrite directive (per depthfirst guidance via THN).
