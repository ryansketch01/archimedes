# PraisonAI CVE-2026-44338 — Authentication-Bypass Mass-Scanner Probing Within 3h44m of Disclosure (Sysdig)

## Summary

Sysdig detected commodity mass-scanner traffic probing the vulnerable PraisonAI `/agents` endpoint within **3 hours and 44 minutes** of advisory publication on 2026-05-14. The vulnerability (CVE-2026-44338, CVSS v3 7.3 HIGH) is an authentication bypass in PraisonAI's legacy Flask API server, affecting versions 2.5.6 through 4.6.33 (patched in 4.6.34). The scanner identified itself as **CVE-Detector/1.0** and ran two passes 8 minutes apart, each sending approximately 70 requests over 50 seconds — first pass targeting generic disclosure paths, second narrowing to AI-agent surfaces.

Sysdig's own framing characterizes the observation as **"associated with a scanner, not interactive exploitation."** The activity is commodity mass-scanning velocity, not attacker-driven post-exploitation. The 3h44m discovery-to-probe figure is the headline, more so than the CVSS 7.3 itself.

A&D-prime direct relevance is LOW-to-INDIRECT. PraisonAI is a Python AI-agent framework not directly used in classified A&D environments, but any A&D firm running AI experimentation labs / proof-of-concept innovation pipelines / engineering-tooling AI integrations may have PraisonAI deployment in the shadow-IT or skunk-works tier. Internal AI inventory audit should include PraisonAI as a check item.

The finding is graded B2 single-source-veto-applied, WEP capped at "likely". Eligible for daily-brief-monitoring (not action-item) given the CVSS 7.3 HIGH (not Critical) and the Sysdig hedge that the activity is mass-scanning not interactive exploitation. Recommended bundle with finding-2026-05-14-0002 (NGINX Rift) and finding-2026-05-14-0003 (Linux LPE cluster) into a "May 14 broad-base patch-cycle pressure" cluster narrative.

## Technical detail

### Vulnerability

CVE-2026-44338 affects PraisonAI versions 2.5.6 through 4.6.33, which shipped with a legacy Flask API server having authentication disabled by default. Unauthenticated attackers can access the `/agents` endpoint and trigger configured workflows via `/chat` without authentication tokens.

- **CVSS v3 base score:** 7.3 HIGH
- **CVSS v3 vector:** AV:N/AC:L/PR:N/UI:N/S:U/C:L/I:L/A:L (network, low complexity, no privileges required, no user interaction, unchanged scope, partial confidentiality / integrity / availability impact)
- **Patched in:** PraisonAI 4.6.34
- **Patch availability:** Concurrent with disclosure

### Scanner observation (per Sysdig)

- **Discovery-to-probe time:** 3 hours 44 minutes from advisory publication to scanner detection
- **Scanner User-Agent:** CVE-Detector/1.0
- **Scanner traffic pattern:**
  - Two passes 8 minutes apart
  - ~70 requests over ~50 seconds per pass
  - First pass: generic disclosure paths
  - Second pass: narrowed to AI-agent surfaces

Sysdig's own framing (paraphrased — Sysdig's own quote held to under 15 words per Hard Rule 6): the activity is associated with a scanner, not interactive exploitation. Sysdig further notes that achieving remote code execution "is not straightforward, as the unauthenticated attacker can only trigger what agents.yaml is configured for." (Within 15-word quote limit.)

### Impact bounded by agents.yaml configuration

The vulnerability allows triggering of configured workflows — impact depends on what workflow permissions are granted to the system via `agents.yaml`. A PraisonAI installation with minimal-permission agent workflows has lower exploitation impact; an installation with broad-permission agents (file access, shell-out, external API calls, secret access) has higher exploitation impact.
