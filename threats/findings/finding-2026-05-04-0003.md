# Backdoored PyTorch Lightning 2.6.3 on PyPI dropped 'ShaiWorm' credential stealer; Lightning AI reverted to 2.6.1

## Summary

Microsoft Threat Intelligence detected a malicious release of `pytorch-lightning` 2.6.3 on PyPI that activates on import, fetches Bun v1.3.13 from GitHub, and runs an 11.4 MB obfuscated JavaScript payload (`router_runtime.js`) that harvests `.env` files, API keys, GitHub tokens, browser data (Chrome, Firefox, Brave), and AWS/Azure/GCP cloud credentials, with arbitrary command execution capability. Microsoft named the family ShaiWorm in Defender. Lightning AI reverted the official package to 2.6.1; investigation into how the build/release pipeline was compromised is ongoing. Microsoft reported a "small number of devices" affected per its telemetry. PyTorch Lightning is a widely-used ML training framework — A&D primes running ML/AI engineering programs (autonomy, computer vision, sensor fusion, predictive maintenance) likely have it in their dev-toolchain inventory.

## Technical detail

- **Package:** `pytorch-lightning` (PyPI)
- **Malicious version:** 2.6.3 (since reverted by Lightning AI)
- **Reverted to:** 2.6.1
- **Distribution method:** Compromise of the official build/release pipeline — NOT typosquat. (This raises the severity profile vs. typical typosquat campaigns.)
- **Detection name:** ShaiWorm (Microsoft Defender)
- **Activation:** On import
- **Stage 1:** Downloads Bun runtime (v1.3.13) from GitHub
- **Stage 2:** Executes `router_runtime.js` — 11.4 MB heavily obfuscated JavaScript payload
- **Scope of theft:** `.env` files, API keys, GitHub tokens, browser data (Chrome, Firefox, Brave), AWS/Azure/GCP cloud credentials, arbitrary command execution
- **Reported impact:** "Small number of devices" per Microsoft telemetry; investigation into pipeline compromise mechanism still ongoing.
- **No file hashes, C2 domains, or IPs disclosed in the BleepingComputer article.**

## Open questions for analyst

- **Pipeline compromise vector unknown:** "How was the official Lightning AI build/release pipeline accessed?" Possibilities: maintainer credential theft, CI/CD token compromise, malicious insider, or PyPI account takeover. Each implies a different defensive lesson for A&D primes' own internal Python release pipelines. SAT-ACH worthwhile if/when MSTIC or Lightning AI publishes the post-mortem.
- **Dev-toolchain exposure scope on watchlist primes:** Worth a coordinated `requirements.txt` / `Pipfile.lock` / `poetry.lock` audit across A&D ML programs for any pull of `pytorch-lightning==2.6.3` between PyPI publication date and the revert. SBOM diffing is the controlled mechanism — not a probe of third-party systems.
- **Credential blast radius:** Stealer targets GitHub tokens and cloud credentials specifically. If any A&D engineering workstation pulled 2.6.3, the response playbook is full credential rotation across affected scopes (GitHub PATs, cloud roles, browser-stored creds, .env contents). This is a defensive consideration, not an Archimedes action item.
