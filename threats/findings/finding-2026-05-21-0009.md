# BleepingComputer reports Google accidentally exposed Chromium Service Worker persistence-RCE issue-tracker entry for ~24h on 2026-05-20; researcher confirmed exploit still functional on Chrome Dev 150 + Edge 148; no CVE assigned (single-source B3, monitoring tier)

## Summary

BleepingComputer (Bill Toulas) reports that Google accidentally re-exposed an unfixed Chromium issue-tracker entry on 2026-05-20, with the entry publicly accessible for approximately 24 hours before being re-restricted. The bug — originally reported December 2022 by independent security researcher Lyra Rebane — was marked "Fixed" by Google on 2026-02-12 without a patch shipping. Rebane confirmed via 2026-05-20 reproduction that the exploit remains functional on Chrome Dev 150 and Edge 148. The mechanism class is Service Worker persistence — a malicious webpage registers a Service Worker that continues executing JavaScript on visitor devices after the browser is closed. No CVE assigned. No active in-the-wild exploitation reported. The article extends the exposure claim to all Chromium-derived browsers (Chrome, Edge, Brave, Opera, Vivaldi, Arc). Single-source veto applies — no independent A/B-grade source (Google Security Blog, Project Zero, Chromium security team, or competing security-media outlet) has corroborated the disclosure-incident in window.

### Mechanism class (researcher framing per BleepingComputer relay)

A malicious webpage registers a Service Worker that "never terminates," persisting JavaScript execution on visitor devices after the browser window is closed. Researcher characterization (under 15-word quote limit): "permanent JS botnet member." No user interaction beyond the initial page visit is required. The mechanism class is consistent with known Service Worker lifecycle semantics in the web-security literature — Service Workers are designed to outlive page navigation for offline-app support, and a worker that fails to terminate at intended lifecycle boundaries can produce persistence properties.

- Edge 148

- Opera

### Exploitation status

- **Active in-the-wild exploitation**: Article reports no evidence of ITW exploitation.
- **Public PoC**: Not explicitly released. Researcher demonstrated vulnerability but technical details remained controlled until 2026-05-20 accidental exposure.
- **Researcher characterization of post-exposure exploitability**: "pretty easy" given the now-public detail.
- **CVE**: None assigned per article.

### Vendor response

Google re-restricted the issue-tracker entry shortly after exposure was noticed. No new patch shipped as of article publication. The earlier "Fixed" status (2026-02-12) is described as demonstrably inaccurate per Rebane's 2026-05-20 reproduction. Google has not commented publicly via own channel per the article.

### A&D-prime relevance — Tier-1 direct (Archimedes-side framing, B3)

Every dev workstation at a prime or Tier-1 supplier running Chrome / Edge / Brave / Opera / Vivaldi / Arc is structurally inside the blast radius. Microsoft Edge is the default browser on managed Windows endpoints across CMMC L2/L3 enclaves. Background-JavaScript-after-browser-close enables persistent foothold on developer / engineer machines without traditional binary persistence (no installer, no scheduled task, no registry edit — just a Service Worker registration from a malicious web visit).

The exposure window (~24h public Chromium tracker entry on 2026-05-20) creates an asymmetric defender disadvantage: well-resourced adversaries continuously monitoring the Chromium issue tracker had a head start on weaponization that ordinary defenders did not. This is hypothetical adversarial-modeling — not an attribution claim — per Hard Rule 2.
