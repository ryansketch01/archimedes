# Microsoft confirms active attack on Dirty Frag Linux kernel LPE chain; rxrpc half remains unpatched

## Summary

Microsoft Security Blog published "Active attack: Dirty Frag Linux vulnerability expands post-compromise risk" on 2026-05-08T17:12 UTC, escalating Dirty Frag from "PoC released, exploitation imminent" (finding-2026-05-08-0001 morning posture) to "active attack underway." MSTIC frames Dirty Frag as a multi-component LPE chain combining CVE-2026-43284 (xfrm-ESP page-cache write — patched upstream commit f4c50a4034e6 merged 2026-05-07) and CVE-2026-43500 (RxRPC page-cache write — unpatched). Distributions are rolling the xfrm-ESP fix; the RxRPC fix is pending. Defenders are in a half-patched state. SANS ISC corroborates the procedural facts and republishes Microsoft's mitigation guidance (modprobe blocklist for rxrpc on systems that do not require it).

The active-attack claim rests on Microsoft Defender telemetry. SANS ISC does not have independent telemetry on in-the-wild exploitation — single-source veto applies on the in-the-wild leg. WEP "likely" rather than "very likely" until a second A-grade vendor publishes independent active-attack observations.

## Technical detail

**CVE-2026-43284 (xfrm-ESP page-cache write):**
- Linux kernel xfrm-ESP (esp4 / esp6) subsystem
- Patched upstream commit f4c50a4034e6 merged 2026-05-07
- Distributions rolling fixes (Ubuntu, RHEL, CentOS Stream, AlmaLinux, Fedora, openSUSE, OpenShift)

**CVE-2026-43500 (RxRPC page-cache write):**
- Linux kernel RxRPC subsystem
- UNPATCHED upstream as of 2026-05-08
- Mitigation: `modprobe` blocklist of `rxrpc` on systems that do not require it

**Exploitation context per MSTIC:**
- Post-compromise privilege escalation — does not provide initial access
- Triggers after attacker has any local foothold (SSH, web shell, container escape, low-privileged account)
- "Designed to increase consistency across vulnerable environments" — paraphrased; relies on multiple kernel attack paths to improve exploitation reliability versus narrow-timing-window LPEs typical in this class

**Comparison to Copy Fail (CVE-2026-31431):**
- MSTIC explicitly compares Dirty Frag to Copy Fail
- Both abuse Linux page cache for LPE
- Copy Fail was disclosed approximately two weeks earlier and is KEV-listed (2026-05-01)

## A&D-target relevance

Half-patched Linux LPE under active attack is operationally relevant to any A&D environment running Linux at scale:
- Build infrastructure (most CI/CD farms)
- Container host fleets (OpenShift explicitly named)
- VPN/IPsec appliances using xfrm
- File-server / Coda / AFS deployments using RxRPC (uncommon but present in some enterprise estates)

The post-compromise nature elevates the "any-foothold-becomes-root" risk ceiling until both halves are patched. MSTIC does not call out A&D sector specifically; the risk is horizontal across Linux estates.

## Analytic notes (from analyst review)

KAC stress-tested seven assumptions underlying the "likely" assessment. Three classify as sound (single-source veto correctly applied; LPE timeline within historical norms; modprobe blocklist deployable for most estates), three qualify (RxRPC patch tempo uncertain; A&D Linux estate composition heterogeneous; MSTIC telemetry is critical-centrality with medium confidence), and one warrants test-class scrutiny (A2 — realistic exposure surface for the RxRPC kernel module).

The strongest analytic point: A2 is critical-centrality with low confidence. RxRPC is not loaded by default on most enterprise Linux distros — it is a niche module supporting AFS/Coda file systems. If the realistic exposure surface across A&D estates is "hosts that have actively loaded rxrpc" rather than "all hosts running affected kernels," the population at risk drops sharply and modprobe blocklist becomes a near-complete mitigation. This narrows the half-patched-state risk envelope materially, but does not flip the "likely" WEP — it sharpens the framing.

Assessment is robust. No downgrade required. Briefer should carry the qualifying caveats into the vuln-update block and watch the 72h tripwire on second-vendor active-attack confirmation (would lift the veto and permit WEP "very likely").
