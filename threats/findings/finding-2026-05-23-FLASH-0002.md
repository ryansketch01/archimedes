# LiteSpeed cPanel Plugin CVE-2026-48172 — CVSS 10.0 vendor self-disclosure with vendor-confirmed active exploitation; lsws.redisAble root RCE from any cPanel user; patch shipped

## Summary

LiteSpeed Technologies disclosed 2026-05-21 a critical privilege-escalation vulnerability in its LiteSpeed User-End cPanel Plugin (CVE-2026-48172). The `lsws.redisAble` function permits any cPanel user to execute arbitrary scripts as root, classified as Incorrect Privilege Assignment (CWE-269). The vendor states the vulnerability is being actively exploited in the wild and has released patched versions v2.4.5 (standalone) and v2.4.7 (bundled in WHM plugin v5.3.1.0). The Hacker News relay 2026-05-23 frames CVSS as 10.0 (LiteSpeed's advisory does not publish a CVSS number; NVD direct-retrieval pending). No actor is attributed; no A&D-prime is named as victim. A&D-prime direct relevance is low — cPanel is not standard prime infrastructure — but structural-indirect supply-chain exposure via sub-tier suppliers and small-vendor web hosting in the A&D ecosystem is meaningful. This is the third CVSS 10.0 vendor disclosure in 60 hours.

## Technical detail

**CVE record:**
- CVE: CVE-2026-48172
- CWE: CWE-269 Incorrect Privilege Assignment
- CVSS: 10.0 (per THN coverage; NVD direct-retrieval pending)
- Researcher credit: David Strydom (independent — no employer named in vendor advisory)

**Affected product and versions:**
- Product: LiteSpeed User-End cPanel Plugin
- Affected: v2.3 through v2.4.4
- Fixed: v2.4.5 (standalone); v2.4.7 (bundled in WHM plugin v5.3.1.0)
- NOT affected: WHM plugin (administrative-side counterpart)

**Vulnerability mechanism (per LiteSpeed advisory, 15-word citation per Hard Rule 6):**

> "Any cPanel user may exploit lsws.redisAble function to execute arbitrary scripts as root."

The vulnerable surface is the `lsws.redisAble` function exposed to cPanel users via the cPanel JSON API (`cpanel_jsonapi_func=redisAble`). The function executes with root context despite being callable from any cPanel tenant account — a classic privilege-assignment failure in the multi-tenant cPanel architecture. Hard Rule 3 compliance: Archimedes does NOT generate or speculate about exploitation-chain detail; LiteSpeed's advisory itself withholds full PoC code.

**Active exploitation (vendor-attested, single-source at sweep time):**

> "This vulnerability is being actively exploited, and poses a risk for all user-end plugin versions between v2.3 and v2.4.4."

Vendor-on-own-product first-person attestation is the strongest exploitation-claim class available, but at sweep time there is no independent telemetry corroboration — Mandiant, Volexity, Unit 42, GreyNoise, and MSTIC are all silent on CVE-2026-48172. CISA KEV is not listing the CVE as of the 2026-05-22 catalog; KEV resurface check is scheduled for the 12:00 EDT sweep. Single-source veto applies on the ITW-exploitation claim layer — WEP capped at 'likely' on that specific layer.

**Detection mechanism (vendor-published):**

```
grep -rE "cpanel_jsonapi_func=redisAble" /var/cpanel/logs /usr/local/cpanel/logs/ 2>/dev/null
```

The advisory directs administrators to review IP addresses observed invoking this jsonapi function and block any non-legitimate sources. **LiteSpeed publishes NO attacker IPs, domains, or hashes** — the IOC layer is detection-grep-pattern-only at vendor publication time.

**Mitigation (per vendor advisory):**
1. Upgrade to WHM plugin v5.3.1.0 + cPanel plugin v2.4.7 (or v2.4.5 standalone) immediately
2. If unable to upgrade, uninstall the user-end plugin: `/usr/local/lsws/admin/misc/lscmctl cpanelplugin --uninstall` (eliminates the vulnerable surface)
3. Hunt for prior exploitation using the published grep pattern; block any non-legitimate source IPs returning hits
