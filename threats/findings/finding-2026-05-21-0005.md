# NLnet Labs Unbound dual criticals — CVE-2026-42960 (CVSS 10.0 DNS cache poisoning) + CVE-2026-33278 (CVSS 9.8 DNSSEC validator pointer-overwrite, DoS + potential RCE) — both patched in Unbound 1.25.1

## Summary

NLnet Labs (vendor of Unbound, one of the most widely-deployed
open-source recursive DNS resolvers globally) and NIST NVD jointly
disclosed two critical vulnerabilities in Unbound on 2026-05-20.
CVE-2026-42960 is a DNS cache poisoning bug exploiting promiscuous
authority-section RRSets — CVSS 10.0 (scope-changed, high-integrity,
high-availability). CVE-2026-33278 is a DNSSEC validator pointer-
overwrite during deep copy producing DoS with potential RCE — CVSS
9.8 (full CIA-triad). Both patched in Unbound 1.25.1 at disclosure.
No active exploitation reported. No actor attributed. The widely-
deployed-DNS-resolver class makes this a strong vuln-tracker
candidate even without ITW attestation.

## Technical detail

### CVE-2026-42960 — Unbound DNS cache poisoning (CVSS 10.0)

- CVSS v3.1: **10.0 CRITICAL** — AV:N/AC:L/PR:N/UI:N/S:C/C:N/I:H/A:H
- Class: DNS cache poisoning via promiscuous authority-section
  RRSet caching
- Affected: NLnet Labs Unbound through version 1.25.0
- Fixed: Unbound **1.25.1**
- Active exploitation: not observed at publication

### CVE-2026-33278 — Unbound DNSSEC validator pointer-overwrite (CVSS 9.8)

- CVSS v3.1: **9.8 CRITICAL** — AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:H/A:H
- Class: DNSSEC validator vulnerability — DoS and potential RCE
  via pointer-overwriting bug during deep copying of data
  structures. When DS sub-queries suspend due to NSEC3 budget
  exhaustion, a struct-assignment error causes dangling pointer
  dereference after memory region cleanup.
- Affected: NLnet Labs Unbound 1.19.1 through 1.25.0 (narrower
  scope; bug introduced post 1.19.1)
- Fixed: Unbound **1.25.1**
- Active exploitation: not observed at publication

### Significance — DNS resolver class is critical infrastructure

NLnet Labs Unbound is one of the most widely-deployed open-source
recursive DNS resolvers globally. Production deployments include
enterprise on-prem recursive resolver deployments at scale, Linux
distribution default-resolver packages (Debian/Ubuntu, Red Hat-
family, OpenBSD/FreeBSD, Alpine), cloud-provider DNS infrastructure
(some hyperscalers), privacy-DNS service infrastructure, and
ICANN-adjacent infrastructure (NLnet Labs is itself a major DNS
ecosystem contributor).

Ecosystem-impact chain framing (Archimedes-side defensive context,
B3 layer):

1. DNS cache poisoning at a corporate recursive resolver enables
   attacker-in-the-middle on certificate-authority validation
   domain control, enabling fraudulent certificate issuance,
   enabling downstream MITM on TLS traffic.
2. DNS-poisoning bypasses HSTS and TLS preflight for any TLS
   connection where the attacker can impersonate the destination
   server with a fraudulent cert obtained via (1).
3. DNS-poisoning at a corporate resolver affects all clients
   behind that resolver — not a per-endpoint compromise but a
   network-segment-wide compromise.
4. DNSSEC validator RCE on the same resolver (CVE-2026-33278)
   would provide direct code execution on the DNS infrastructure
   itself — bypassing the "poisoning" indirection entirely.

The pair is operationally complementary: cache poisoning provides
the network-wide impact class; DNSSEC RCE provides direct resolver-
process control. Both patched in 1.25.1.

## A&D-prime relevance — STRUCTURAL, NETWORK-INFRASTRUCTURE LAYER

A&D primes universally run recursive DNS resolvers at internet
egress and intra-network resolution layers. Unbound deployment
posture at A&D primes is plausibly material but not publicly
enumerable:

- Corporate enterprise resolver deployments likely use a mix of
  Unbound, BIND, Microsoft DNS, and vendor-appliance resolvers
  (Infoblox, BlueCat). Unbound is common at the BSD/Linux-side of
  the resolver mix; BIND remains the more common large-enterprise
  default; Microsoft DNS dominates AD-integrated environments.
- OT / process-control network resolvers sometimes deploy Unbound
  or other lightweight resolvers in segmented OT segments.
- CMMC enclave resolvers — Unbound is well-suited to high-security
  configurations (small attack surface, DNSSEC validation, privacy-
  focused defaults).
- R&D / lab environment resolvers — Linux research environments
  commonly default to Unbound or systemd-resolved (which can use
  Unbound as upstream).

Per Hard Rule 2, Archimedes does not name specific A&D-prime
Unbound deployments. Sector-shape framing only.
