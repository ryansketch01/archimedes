# EvilTokens PhaaS — OAuth device-code phishing platform live February 2026 — 340+ M365 organizations compromised across 5 countries in 5 weeks per CSA Research Note

## Summary

The Hacker News relays a Cloud Security Alliance (CSA) Research Note dated 2026-03-25 on EvilTokens, a Phishing-as-a-Service (PhaaS) platform that went live in February 2026. Within five weeks of launch, EvilTokens had compromised more than 340 Microsoft 365 organizations across five countries (countries unspecified). The tradecraft mechanism is OAuth 2.0 device-code phishing: target enters a short code at microsoft.com/devicelogin, completes a normal MFA challenge, walks away believing they have verified a normal sign-in — while the device-code flow grants the operator long-lived refresh tokens. Refresh tokens survive password resets and remain valid weeks-to-months; closure requires explicit token revocation, not password rotation. No tracked-actor attribution. No specific victim sectors named. No A&D-prime victim named. No IOCs surfaced. EvilTokens is the third 2026 corpus instance of an OAuth-device-code PhaaS class alongside Tycoon2FA (finding-2026-05-17-0002, eSentire-attributed) and Storm-2949 (morning-brief carry-forward, MSTIC-attributed); per Hard Rule 2, Archimedes does NOT propagate either prior attribution to EvilTokens.

## Technical detail

**Platform:** EvilTokens — PhaaS platform live since February 2026.

**Scale (per CSA via THN):** More than 340 Microsoft 365 organizations compromised within 5 weeks of launch across 5 countries (countries unspecified).

**Tradecraft mechanism (conceptual flow-of-operations):**

1. Target receives a message asking them to enter a short code at microsoft.com/devicelogin
2. Target completes their normal MFA challenge
3. Target walks away believing they have verified a normal sign-in
4. Behind the scenes, the device-code flow grants the operator long-lived **refresh tokens**
5. The operator never needed a password, never tripped an MFA prompt, never produced a sign-in event that looked like an intrusion (CSA framing paraphrased)
6. Refresh tokens survive password resets and remain valid weeks-to-months depending on tenant configuration
7. Closure requires explicit token revocation, not password rotation

**Mechanism corroboration (independent A1 references — DIFFERENT actors using same mechanism class):**

- MSTIC Storm-2372 February 2025 (device-code phishing)
- Volexity Russian SVR 2025 (device-code phishing)
- MITRE ATT&CK T1528 token theft sub-technique
- OAuth 2.0 RFC 8628 device authorization grant flow (mechanism specification)

**Tradecraft-class siblings (Archimedes-recorded, NOT single-actor attribution):**

1. **Tycoon2FA** (finding-2026-05-17-0002) — device-code PhaaS, similar OAuth abuse pattern, different vendor naming, eSentire-attributed
2. **Storm-2949** (morning-brief carry-forward — Microsoft MSTIC originating-research) — identity-driven M365/Azure cloud-pivot tradecraft including device-code abuse class
3. **CORDIAL SPIDER + SNARKY SPIDER** (CrowdStrike 2026-04-30 voice-phishing AiTM SaaS) — earlier in the year; different specific tradecraft (vishing AiTM, not device-code phishing) but adjacent SaaS-impersonation class

The industry-wide pattern is a PhaaS arms-race against M365 device-code and OAuth consent flows. Archimedes does not extrapolate from class observation to a single tracked actor.
