# YellowKey + GreenPlasma — Windows BitLocker Bypass + LPE Zero-Days Disclosed with Public PoCs, No Patch (BleepingComputer 2026-05-13)

## Summary

A pseudonymous researcher operating as Chaotic Eclipse (GitHub handle
Nightmare-Eclipse) published proof-of-concept exploits for two
previously undisclosed Windows vulnerabilities on 2026-05-13: **YellowKey**,
a BitLocker bypass technique exploiting NTFS transactions in the
Windows Recovery Environment that defeats TPM-only configurations on
the original device; and **GreenPlasma**, a CTFMON local privilege
escalation enabling arbitrary memory-section creation in SYSTEM-writable
directories. BleepingComputer (Bill Toulas byline) is the single
B-grade media source covering the disclosure; no MSRC advisory, no
CVE assignment, no CISA KEV addition, and no Tier-1 vendor research
has surfaced at grading time. Microsoft acknowledged the report with
no timeline commitment. The cluster grades B3 (Possibly True via
single-source uncorroborated B-grade origin) and ships as a
monitoring-tier finding with WEP "likely" capped via single-source
veto. Operator-actionable framing centers on BitLocker hardening
posture (TPM-only → TPM+PIN transitions where feasible; BIOS
passwords; supply-chain / facility-physical-access threat model
applicable rather than remote-network).

## Technical detail

### YellowKey — BitLocker bypass via NTFS-transaction manipulation in WinRE

- **Class:** Boot-environment privilege escalation to BitLocker drive
  decryption
- **Mechanism (per BleepingComputer):** Specially crafted FsTx files
  placed on a USB drive or copied to the EFI partition; pressing
  CTRL during boot triggers a shell within the Windows Recovery
  Environment via NTFS transaction processing
- **Configuration affected:** TPM-only BitLocker (the most common
  enterprise configuration where users do not enter a PIN at boot)
- **Original-device requirement:** YellowKey explicitly does NOT
  decrypt stolen drives — the TPM key release still requires the
  original platform. The threat model is recovery / re-access /
  facility-physical access to the original hardware, not pure
  drive-theft
- **Affected platforms:** Windows 11, Windows Server 2022, Windows
  Server 2025 (per article)
- **Researcher claim:** TPM+PIN is also exploitable in research
  (PoC not published for that variant)
- **Mitigation cited in article:** Combine BitLocker PIN with a BIOS
  password (defeats the published YellowKey PoC against TPM-only)
- **CVE:** Not assigned at disclosure
- **Patch:** Not available at disclosure
- **Public PoC:** github.com/Nightmare-Eclipse/YellowKey (research
  artifact, not actor infrastructure; not added to IOC index per
  Hard Rule 3 / standard IOC-classification rules)

### GreenPlasma — CTFMON arbitrary memory-section creation LPE

- **Class:** Local privilege escalation to SYSTEM
- **Mechanism (per BleepingComputer):** "Windows CTFMON Arbitrary
  Section Creation Elevation of Privileges." Allows unprivileged
  users to create arbitrary memory-section objects in SYSTEM-writable
  directories
- **Researcher characterization:** PoC published is "incomplete";
  researcher claims full SYSTEM-shell exploitation is achievable
- **Affected platforms:** Same as YellowKey (Windows 11/Server
  2022/Server 2025 per article framing)
- **CVE:** Not assigned at disclosure
- **Patch:** Not available at disclosure
- **Public PoC:** github.com/Nightmare-Eclipse/GreenPlasma

## A&D structural relevance

No A&D prime is named. Structural relevance is universal but
narrower than the OS deployment surface suggests:

1. **CMMC / NIST 800-171 / FIPS context.** BitLocker is the
   canonical Windows full-disk-encryption implementation that
   satisfies CMMC Level 2 (NIST SP 800-171 control 3.13.16,
   "Protect the confidentiality of CUI at rest"), NIST 800-53
   SC-28, and FIPS 140-2/3 cryptographic-module requirements when
   configured per FIPS-mode guidance. Every prime on
   aerospace-defense.yaml deploys BitLocker for CUI-at-rest
   protection on Windows endpoints.

2. **Threat model is physical-access / supply-chain / insider /
   evil-maid, NOT remote.** YellowKey requires write access to the
   EFI partition or a USB drive at the target system's physical
   location. The original-device requirement narrows the surface
   further: stolen drives are NOT decrypted by YellowKey. The
   operator-actionable surface is therefore:
   - Traveler-laptop programs (encrypted laptops handled outside
     controlled spaces and re-accessed by adversaries)
   - Supply-chain shipped pre-loaded devices (intercept-and-modify
     attack class)
   - SCIF / classified-handling laptop programs at facility
     re-entry
   - Any program that depends on BitLocker for CUI-at-rest on
     systems leaving controlled spaces

3. **GreenPlasma's LPE class is broader.** Any local user account
   on an affected Windows host could in principle escalate to
   SYSTEM if the full chain is weaponized. The published PoC is
   described as incomplete; immediate operational impact is
   bounded by that gap.

Per Hard Rule 2, this finding does NOT assert specific prime
impact — only that the affected surface is universal Windows
deployment with the threat-model caveats above.
