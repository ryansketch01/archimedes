# CISA adds CVE-2026-42208 (BerriAI LiteLLM pre-auth SQL injection, CVSS 9.3) to KEV with aggressive 3-day federal patch deadline

## Summary

CISA added CVE-2026-42208 to the Known Exploited Vulnerabilities catalog at 2026-05-08T12:00 UTC with a 2026-05-11 federal patch deadline — a 3-day window versus the typical 14-21 day KEV deadline. The CVE is a pre-authentication SQL injection in BerriAI LiteLLM (an AI-gateway proxy that brokers requests across multiple LLM backends including OpenAI, Anthropic, Google, and Azure). Pre-window Sysdig honeypot telemetry from 2026-04-26 documented first observed exploitation 26 hours and 7 minutes after the GitHub Advisory Database disclosure on 2026-04-24. Bishop Fox vulnerability research established the exploitation mechanism (Authorization Bearer header concatenated into SQL query without parameterization) and CVSS 9.3 score. The compromised pivot is upstream LLM API credential theft from `litellm_credentials.credential_values` — i.e., theft of OpenAI, Anthropic, Google API keys cached by the proxy.

The aggressive 3-day federal deadline signals CISA's assessment of either active high-severity exploitation in federal networks or rapidly-spreading exploitation observed externally with imminent federal-network exposure.

### WAF mitigation pattern

Bishop Fox guidance (paraphrased): block requests with SQL metacharacters (single quote, semicolon, UNION/SELECT keywords) in the `Authorization: Bearer` header field. This is mitigation guidance, not exploitation assistance.

## A&D-target relevance

LiteLLM is an AI-gateway middleware brokering credentials across multiple LLM backends. The compromise pivots to upstream LLM API key theft, not direct enterprise compromise. A&D-relevance considerations:

- **A&D AI gateway adoption:** A&D primes are deploying internal AI gateways for engineer productivity. LiteLLM is one option among several. ITAR-regulated shops typically air-gap or use cleared cloud (GovCloud, AWS Top Secret region) — internet-exposed LiteLLM is unusual but not zero. Tier-2 / Tier-3 supplier exposure is harder to bound.
- **Pre-auth means no auth required:** Anything reachable on the internet is exploitable.
- **Supply-chain pivot:** A compromised contractor LiteLLM proxy yields all upstream LLM credentials cached by that proxy — enabling downstream impersonation of the contractor's queries to upstream LLM providers, model-poisoning of contractor-side agents, or covert data exfiltration via crafted LLM queries.

This is the second active-exploitation KEV-listed CVE in the Archimedes vuln-tracker corpus alongside ZD-004 (PAN-OS CVE-2026-0300). Pattern: CISA is moving aggressively on AI-supply-chain and edge-network products. Vuln-tracker should consider opening a dossier.

## Analytic notes (from analyst review)

KAC stress-tested seven assumptions underlying the assessment. Two classify as sound (pre-auth attack surface plausible; LiteLLM credential storage in database is the standard deployment pattern), four qualify (LLM-credential-pivot impact bounded by tenant-scoping; FCEB deadline does not equal A&D contractor deadline; Sysdig honeypot generalization uncertain; AI-supply-chain TTP class is emerging not established), and one warrants test-class scrutiny (A1 — A&D LiteLLM install base unknown).

A1 is the load-bearing assumption: the entire A&D-relevance framing rests on whether A&D contractors run LiteLLM gateways at meaningful scale, and Archimedes has no evidence either way. ITAR-regulated environments typically air-gap or use cleared cloud, which constrains the realistic exposure surface in primary A&D shops. Tier-2/Tier-3 supplier exposure is plausible but unbounded in open source.

KAC and red-team converge on the same posture-tightening outcome via different routes. Red-team challenged source independence (laundered-pipeline pattern, downgrade to "likely"); KAC challenged A&D-relevance assumption (test-class scrutiny on A1, demote from brief lead). Both passes recommend the briefer treat this as a vuln-update block paired with Ivanti EPMM rather than a standalone A&D-direct lead, with explicit caveats on the FCEB-vs-A&D scope distinction and the inventory-check posture.
