Microsoft (MSTIC / Microsoft Defender Security Research Team) and
Palo Alto Networks Unit 42 — two A-grade Tier-1 threat-intel
vendors — published formal technical analyses on the Mini Shai-
Hulud @antv npm supply-chain campaign on the same day (2026-05-20),
within 2 hours of each other. MSTIC's deep technical analysis
documents novel TTP layers: GitHub Actions Runner.Worker memory
scraping, /proc PID scanning on Linux, Bun runtime payload, PBKDF2-
SHA-256 string obfuscation, SLSA provenance forgery, 1Password CLI
2FA bypass, Kubernetes service account token targeting, AWS Secrets
Manager + HashiCorp Vault enumeration. Unit 42's corpus-level npm
threat landscape update characterizes post-Shai-Hulud evolution
across wormable malware, CI/CD persistence, multi-stage attacks.
Both vendors use unattributed-actor framing; neither independently
corroborates TeamPCP attribution (which stays at the existing VT-006
A2 anchor via prior Wiz + Snyk + StepSecurity + Socket consensus).
The MSTIC analysis does NOT specifically validate the SecurityWeek-
originating Claude-Code-backdoor-drop claim — KAC A1 Test tripwire
on finding-2026-05-20-0001 does NOT close.

## Technical detail

### MSTIC documented novel TTP layers (defensive-context, no PoC)

The novel-TTP layers in MSTIC's analysis represent natural
extensions of the established Mini Shai-Hulud worm class mechanics
(documented in VT-006 dossier) — not new campaign mechanics. They
warrant VT-006 dossier `novel_capability_layers` updates:

1. **GitHub Actions Runner.Worker memory scraping** — extracts
   secrets and tokens from the CI/CD runner process memory at
   build time, capturing credentials that never touched disk.
2. **/proc PID scanning on Linux** — Linux-side credential
   harvesting by enumerating /proc filesystem to identify
   credential-bearing processes for memory targeting.
3. **Bun runtime payload** — execution via the Bun JS runtime
   rather than Node.js, evading Node-specific detection rules.
4. **PBKDF2-SHA-256 string obfuscation** — payload string
   obfuscation using PBKDF2-SHA-256 with campaign-specific salt
   (consistent with VT-006 PBKDF2 campaign-salt-based execution
   guardrails).
5. **SLSA provenance forgery** — consistent with VT-006 novel-
   capability-layer #1 (SLSA provenance attestation breakage).
6. **1Password CLI 2FA bypass** — targets the `op` CLI to
   enumerate password manager vault contents while bypassing
   2FA.
7. **Kubernetes service account token targeting** — harvests
   K8s SA tokens for cluster-resident lateral movement.
8. **AWS Secrets Manager + HashiCorp Vault enumeration** —
   harvests secrets-manager contents via authenticated CI/CD
   credential context.
9. **npm token validation OIDC publish** — validates harvested
   npm tokens via OIDC publish flow, confirming usability before
   downstream exfiltration.
10. **Linux gated payload execution** — conditional payload
    execution based on Linux platform check; consistent with
    PBKDF2-gated execution from VT-006 baseline.
11. **preinstall hook** — payload runs during `npm install`
    preinstall lifecycle, capturing the credential-rich CI/CD
    install context.

## A&D-prime relevance — HIGH (sector-shape only; no A&D-prime named)

CI/CD credential theft via npm supply-chain compromise is universal
in A&D-prime devops estate. The MSTIC-documented novel-TTP layers
specifically extend the attack surface to credential stores commonly
used in A&D R&D pipelines: AWS Secrets Manager (cloud R&D pipelines),
HashiCorp Vault (privileged credential management), Kubernetes
service account tokens (containerized R&D workloads), 1Password CLI
(developer credential vaults), GitHub Actions Runner secrets (CI/CD
pipeline secrets including npm registry tokens, container registry
credentials, code-signing certificates).

No A&D-prime named as victim in either MSTIC or Unit 42 publication.
Sector-shape framing only.
