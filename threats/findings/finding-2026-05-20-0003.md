# Microsoft publishes mitigation for YellowKey BitLocker bypass zero-day (CVE-2026-45585, CVSS 6.8) — actionable for A&D workstation fleets

## Summary

Microsoft (MSRC, 2026-05-19 / 2026-05-20 publication window) publishes mitigation guidance for CVE-2026-45585 (codename YellowKey), a Windows BitLocker security-feature bypass zero-day with CVSS 6.8. The vulnerability was disclosed pre-vendor by an anonymous independent researcher operating under the "Nightmare Eclipse" handle — fifth publicly disclosed zero-day from this researcher lineage following BlueHammer (ZD-001, patched), RedSun (ZD-002, unpatched), UnDefend (ZD-003, unpatched), and GreenPlasma (not yet in `_index.yaml`).

The MSRC mitigation guidance is a 4-step procedure: (1) remove autofstx.exe from Session Manager's BootExecute registry value, (2) reconfigure BitLocker from TPM-only to TPM+PIN mode, (3) require additional authentication at startup via Intune or Group Policy, (4) set "Configure TPM startup PIN" to "Require startup PIN with TPM." A formal patch is not yet released; mitigation guidance is the current Microsoft-published defensive posture.

PoC is publicly available via the Nightmare Eclipse researcher's protest-disclosure; no in-the-wild exploitation claimed by Microsoft (vendor language: "potential attacks exploiting it in the wild" rather than "active attacks"). BleepingComputer (Sergiu Gatlan, 2026-05-20 03:31 EDT) and The Hacker News (2026-05-20 04:28 EDT) provide dual independent B-grade media relay of the MSRC publication.

A&D relevance is structural-medium: BitLocker is universally deployed across A&D workstation and laptop fleets, and ITAR/CMMC compliance often references BitLocker as approved full-disk-encryption. The TPM+PIN reconfiguration mitigation is a posture-improvement directly applicable to A&D defenders via existing Group Policy / Intune deployment paths.
