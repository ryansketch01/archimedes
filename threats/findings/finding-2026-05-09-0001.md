# OpenC3 COSMOS spacecraft C2 software — five-CVE cluster, two Critical, patches available; NASA and BAE Systems on vendor user list

## Summary

OpenC3 COSMOS — open-source command-and-control software for spacecraft, satellite constellations, and embedded systems integration / test / operations — has five CVEs assigned and lastModified within the collection window. Two are Critical: CVE-2026-42087 (CVSS 9.6, SQL injection in the Time-Series Database `tsdb_lookup` function) and CVE-2026-42088 (CVSS 9.6, privilege escalation through the Script Runner Tool's container-share network). One is High (CVE-2026-42084, CVSS 8.1, password reset bypass via session token reuse). Two are Medium (CVE-2026-42085 arbitrary file write to /plugins; CVE-2026-42086 self-XSS in Command Sender via `eval()`). All five were disclosed via vendor GHSAs on 2026-04-20 and patched in OpenC3 COSMOS 7.0.0-rc3 / 7.0.0.

## Technical detail

**CVE-2026-42087 — SQL Injection in Time-Series Database (Critical 9.6)**
- Component: `cvt_model.rb` `tsdb_lookup()` — telemetry data store
- Attack vector: `AV:N/AC:L/PR:L/UI:N/S:C/C:H/I:H/A:N` (network, low complexity, low-privilege required, no UI, scope-changed)
- Exploitation prerequisites: any account with telemetry permission (Admin, Operator, Viewer, Runner) — i.e., low-privilege authenticated user
- Attack path per vendor: injection via the `start_time` parameter of the `get_tlm_values` RPC endpoint, allowing arbitrary SQL execution including data deletion
- Fixed in: 7.0.0-rc3
- Affected versions: 6.7.0 through 7.0.0-rc2

**CVE-2026-42088 — Script Runner Tool Privilege Escalation (Critical 9.6)**
- Component: Script Runner widget executing Python / Ruby in `openc3-COSMOS-script-runner-api` container
- Attack path per vendor: malicious scripts can connect directly to backend services on the shared Docker container network, bypassing the API authorization layer; can read Redis credentials from container env, modify Redis state including secrets and COSMOS settings, read/write configuration / logs / plugin files in the buckets service
- Vendor stated impact: "Data disclosure/manipulation, privilege escalation"
- Fixed in: 7.0.0-rc3

**CVE-2026-42084 — Password Reset via Session Token (High 8.1)**
- Component: password change endpoint
- Attack path per vendor: endpoint accepts a valid session token in lieu of the old password, enabling account takeover for any account whose session token is acquired (admin-account hijacking in scope)
- Affected: pre-6.10.5 and 7.0.0-rc1 / -rc2

**CVE-2026-42085 — Arbitrary File Write to /plugins (Medium 4.3)**
- Component: `save_tool_config()`
- Attack path: caller specifies arbitrary destination path inside the shared `/plugins` directory tree via crafted configuration filename, enabling configuration overwrite or planting

**CVE-2026-42086 — Self-XSS in Command Sender (Medium 4.6)**
- Component: Command Sender UI
- Attack path: UI calls `eval()` on array-like command parameters, executing user-supplied payloads in the browser session at command-send time

**Patch state across the cluster:** All five fixed in 7.0.0-rc3 and the full 7.0.0 release. Operators on 6.7.0 through 7.0.0-rc2 require upgrade to 7.0.0 to close all five.

## Why this matters for A&D target profile

OpenC3 COSMOS is spacecraft / satellite / constellation command-and-control software. The vendor explicitly names NASA and BAE Systems among users; BAE Systems is a Tier-1 prime on the aerospace-defense watchlist. Vendor heritage includes the SBSS satellite program.

Operational considerations specific to spacecraft-C2 software:

- COSMOS deployments at A&D primes would typically sit in spacecraft-test-and-operations enclaves where the C2 instance has reachability — direct or indirect — to live mission systems or test articles
- The Critical 9.6 SQLi (CVE-2026-42087) requires only low-privilege authenticated access (Viewer role qualifies), which lowers the bar for insider abuse or credentialed-attacker pivot from any compromised auxiliary account
- The Critical 9.6 Script Runner escape (CVE-2026-42088) is a container-network trust-boundary failure — once an attacker reaches the Script Runner widget, the container-share network exposes Redis and buckets services without API auth
- The High 8.1 password reset bypass (CVE-2026-42084) enables session-token-to-permanent-account-takeover persistence in any breach scenario where session tokens have been acquired

The patch path is straightforward (upgrade to 7.0.0). The operational question is upgrade tempo: spacecraft-test-and-operations environments typically have constrained change windows, and a major-version bump (6.x → 7.0) may require regression testing of mission scripts and integrations. Estate operators should not assume the federal-typical 30-day envelope applies if change-control gates extend the upgrade timeline.

No A&D-targeting campaign has been reported. No in-the-wild exploitation. The risk is the existence of a low-bar Critical-severity vulnerability cluster in an A&D-relevant software product with public PoC content in the GHSAs, sitting unpatched in any operator estate that has not yet completed the 7.0 upgrade.
